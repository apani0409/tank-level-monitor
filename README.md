# Tank Level Monitor

A small dashboard for IoT tank-level monitoring: 4 tanks, hourly readings, rule-based
leak detection, and days-to-empty estimates.

**Live demo:** https://tank-level-monitor.vercel.app

## Why this exists

Built after reading about [Element System](https://www.elementsystem.com)'s work
automating water infrastructure in Costa Rica — ultrasonic sensors on storage tanks,
remote monitoring, and the Nandayure aqueduct project that cut water loss 15-20% for
1,300 households. This is a small demonstration of that same pattern: sensor readings
in, actionable decisions out.

**Honest framing:** the sensor data here is synthetic, generated by
[`scripts/generate-data.ts`](scripts/generate-data.ts) — there is no real hardware or
real client data behind this. It exists to show the shape of the problem I'd want to
work on: turning a stream of raw measurements into something a person can act on
without staring at a chart.

## What it does

- Time-series chart per tank (30 days of hourly readings)
- Current level, volume in liters, and a low-level threshold line
- **Rule-based leak detection**: compares each tank's drop rate over the last 24h
  against its own historical median drop rate. If it's sustained and more than 1.8×
  the baseline, it flags a possible leak — deliberately simple and explainable rather
  than a black-box model, since an ops team needs to trust *why* an alert fired.
- Estimated days-to-empty at the current consumption rate

One of the four simulated tanks has a leak intentionally injected in the last 18 hours
of its data, specifically to verify the detector fires on a real anomaly and stays
quiet on the other three.

## Stack

React 19 + TypeScript + Vite, Plotly.js for the chart. Fully client-side — no backend,
data is a static JSON file.

## Running locally

```bash
bun install
bun run scripts/generate-data.ts   # regenerates public/tanks.json
bun run dev
```

## Build

```bash
bun run build
```
